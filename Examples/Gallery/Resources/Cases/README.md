# Gallery 核心案例

文档版本：1.1 · 更新日期：2026-11-22

这里维护 Gallery 的十个核心场景。`catalog.json` 是场景、标题、分类、来源和两份程序路径的唯一索引；宿主按所选库读取 `openui/` 或 `openintelligentui/`。程序路径相对本目录，避免把源码嵌在 Swift 菜单中再维护一份。

## 内容范围

| 场景 | 主要检查的体验 |
| --- | --- |
| 杭州周末的四种心情 | 图文叙述、图片网格、地图与继续提问 |
| 杭州南宋与西湖两日 | 时间安排、地点对比、票务承接 |
| 空调制热的原理 | 原理图、分步解释、数量比较 |
| 找到舒服的卧室氛围 | 图片选择、多选状态与动作载荷 |
| 阅读台灯怎么选 | 商品图、比较表、价格与购买入口 |
| Agent 代码执行隔离 | 技术长文、架构图、代码和引用 |
| 带父母慢游苏州 | 交通、住宿、地图和预算边界 |
| 同日直飞与中转比较 | 多段行程、时区、换机场与历史记录 |
| 三个月账单与下月计划 | 堆叠图、统计范围切换、预算对比 |
| 行程联系人本页核对 | 输入、校验、局部状态与宿主动作 |

这些是完整任务场景。组件枚举、性能输入、协议断言和未来的 Agent 服务分别由对应目录负责，不往这里叠加运行时、后端、历史实验或重复导出。

## 与 CaseLab 的关系

选取来源为 [zyfn/openui-case-lab](https://github.com/zyfn/openui-case-lab/tree/903c6ebaa0611bd228b19962e324524175492437)，固定提交为 `903c6ebaa0611bd228b19962e324524175492437`。每项的准确来源路径写在 `catalog.json`。

- 前八份标准程序从本仓库原 `Examples/AgentCases/` 移入，文件名与字节均保持不变；它们与上述 CaseLab 提交的 `Review/Fixtures/SimpleCases/` 逐字一致。CaseLab 原先也是从 SDK 同步这八份内容，因此本次移动没有再导入第二份副本。
- `openui/scene-spending.openui` 和 `openui/behavior-form.openui` 分别提取自 `Review/Catalog/Programs/ReviewExamplePrograms.swift` 的 `scene-spending`、`behavior-form` 中文 `zh-Hans` 分支。仅移除 Swift 原始字符串与源码缩进，DSL 未改写。
- 十份 OpenIntelligentUI 程序按自身组件契约编排，保留 OpenUI 场景的完整内容、阅读层次、来源图片及任务意图。通过 `Col`、`Row`、`Box`、`Image`、`Title`、`Text`、`Caption`、`Carousel`、`Chart`、`ProductCard`、`TransportCard` 等组件组织解释、比较、选择与后续行动。杭州周末与卧室氛围的图文使用这些基础组件组合，图片、标签、说明及原有交互完整保留；不依赖 `ImageText` 生成入口。图文集合使用容器默认布局；需要随可用宽度减少列数时，Grid 提供 `minChildWidth`，程序无需计算用户设备尺寸。

后续修改在这里维护。需要向 CaseLab 同步时，应由其消费这些源文件；不要在两个仓库各改一份后再人工挑选。源项目采用 Thesys MIT 许可，本仓库现有第三方声明保留对应许可。

## 内容完整性与产品表达

OpenUI 的前八份原文继续作为既有行为回归素材。OpenIntelligentUI 保留完整开篇、章节、解释、比较、结论与后续行动；不能为了让示例短小而删去主要内容。探索与候选选择使用横向集合，行程保留逐站照片和说明，商品与交通使用自身业务组件，图解用结构化图元或原生分组表达。补充信息可以折叠，主要解释与结论保持可读；两套产品不要求使用相同的视觉组件。

商品身份、来源链接、价格口径、日期、时区、地点坐标与演示边界保持一致。Gallery 回归检查两套程序的原始媒体/链接保留，以及十个场景的关键章节、数据与交互入口；这些检查不能替代原生画面的视觉验收。

卧室场景用三个显式布尔状态收集多选，并随 `ToAssistant` 动作传递实际选择。账单场景在两套程序中保持相同金额与统计范围。联系人场景中，标准 `Form` 使用其现有字段校验；Intelligent `Form` 负责分组，示例显式绑定字段、检查姓名非空和邮箱基本形态，再把当前字段快照与上次核对比较。这个基础检查不验证邮箱存在，也不是完整的邮箱地址规范实现。

## 图片与外部内容

远程图片 URL 沿用来源资料。这里不下载整套远程图库，也不把不同地点或商品的本地照片映射成同一张图。是否成功加载取决于网络、来源站点与图片权限；离线时应观察宿主和组件真实的占位、错误与重试状态。账单、联系人、热泵和代码隔离场景无需远程照片即可检查核心布局与交互；地图底图和外链仍可能需要网络。

内容的历史依据与价格、行程演示条件见 [CONTENT-SOURCES.md](CONTENT-SOURCES.md)。本次整理没有重新查价或确认库存。商品、机票、酒店和门票入口仅保留原地址；Gallery 的本地动作日志用于调试，未连接 Agent 或提交业务请求。

## 添加或修改场景

1. 先确认场景补足了目前缺少的真实任务，而不是重复展示同一种组件。
2. 在两个库目录各提供可解析的程序，保持稳定 `id` 和同一关键数据口径。
3. 更新 `catalog.json` 的说明、标签与准确来源，保持相对路径指向唯一源码。
4. 使用真实库的解析与流式验证，并在 Gallery 查看窄屏、宽屏、缩放、暗色和较大文字下的效果。检查交互后状态、数据表、图片失败和动作载荷。

静态目录校验和 JavaScript 核心解析不能替代 Apple 平台上的 SwiftUI 编译、测试与视觉检查；验证结果应分别报告。
