# OpenUI

文档版本：1.37 · 更新日期：2026-11-19

OpenUI 提供通用组件目录与原生视觉。包、目录和共享运行机制只见[架构](architecture.md)，安装与状态生命周期见 [README](../README.md)，构建及验收见[验证说明](validation-and-security.md)。本文件统一维护该组件库的用法与呈现约束。

## 接入

在主线程创建并长期持有文档状态：

~~~swift
import SwiftOpenUI

let library: OpenUILibrary = try .openUI()
let state = library.makeState()
state.setSource(#"root = Stack([TextContent("Hello")])"#)
let view = OpenUIView(state: state, library: library)
~~~

向模型提供同一个 library 的 systemPrompt 和 specificationJSON。宿主向 state 输入完整或增量 Lang，并处理 onAction 与 ToolProvider；组件库不负责模型通信或业务结果。

## 组件目录

实际目录由 OpenUIComponents 注册并导出，包括固定上游的 84 个定义，以及原生 Map、MapPoint、SVG 和 JourneyLine，共 88 个定义。其中 73 个是可视定义，15 个是由父组件消费的结构或数据定义；不能把注册数等同于独立可点击控件数量。

Gallery 按 Layout、Content、Controls、DataDisplay、Media 浏览实际注册定义，结构子项标注父组件上下文，组件用法默认展开。签名、位置参数和默认值以 library.specification 为准，不另维护一张手写权威目录。原始参考目录在 [upstream-catalog.json](../Sources/SwiftOpenUI/Resources/upstream-catalog.json)，原生注册在 [Catalog](../Sources/SwiftOpenUI/Catalog/)。

只有实际实现并注册的定义进入生成契约。Swift 包名、文件归属和视觉调整不改变已支持的 Lang 组件名、参数顺序、绑定和枚举。

Steps 默认仍为数字步骤；`Steps(items, "timeline")` 显示行程时间线，`StepsItem(title, details, time?)` 的时间仅在已知时填写。可选参数均追加在原参数后，旧调用不变。`variant` 的完整性使用 SDK 公共布局依赖机制判断。流式生成建议先输出 `root = Steps(items, "timeline")`，再逐步输出 `items`，使样式可以先确定；行内列表尚未到达尾部样式参数时，先呈现已到达的文字，避免预先猜测节点样式，样式确定后字号和缩进仍可能调整。生成中断且样式始终未确定时，已完成的条目回退到默认数字步骤；已经确定的时间线样式保持不变。未闭合的时间值不会作为完整时间显示。

交通方向线使用 `JourneyLine(mode)`，沿用设计师的四种方式 `flight`、`train`、`bus`、`taxi` 和虚线造型；它只表达起终点方向，不代表地图路线。

普通主题页签使用 `Tabs(items)` 或 `Tabs(items, "default")`。按具体日历日切换时使用 `Tabs(items, "date")`。两者都使用 `TabItem(value, trigger, content)`。日期项的 `value` 是唯一的 `YYYY-MM-DD`，`trigger` 填短星期名，按钮在星期下方显示日号。

两种样式都默认打开声明顺序中的第一项。流式追加正文或页签时保留当前页，用户点选后按 `value` 保持选择。确认当前项已移除才回到首个可用项。建议先声明 `days = Tabs([sat, sun], "date")`，再填各项正文。长正文直接内联时，尾部样式尚未确定也能阅读和选择已就绪的页签，确定样式后再绘制对应的选中装饰。中断时尚未写完的样式回退为普通页签。

使用标准库的宿主可以继续读取历史单参 Tabs。曾自行导出 `Tabs(items, $value)` 的宿主应在覆盖定义中固定第二位为 `value`，将可选 `variant` 追加在该宿主签名的末尾。直接向新版标准参数列表末尾追加绑定会把绑定移到第三位。生成端应使用对应宿主实际导出的契约。

## 组件定义与扩展

SwiftLang 提供 OpenUIComponent、OpenUIComponentLibrary 和 OpenUIParameter；组件将有序参数与原生 View 放在同一注册定义中。自建目录通过 OpenUILibrary(components:) 接入统一状态和 View。

~~~swift
let components = try OpenUIComponentLibrary(
    components: [
        OpenUIComponent(
            name: "Notice",
            description: "Display supplied text",
            params: [OpenUIParameter.string("text")]
        ) { context in
            Text(context.string("text") ?? "")
        }
    ],
    root: "Notice"
)
let library = OpenUILibrary(components: components)
let state = library.makeState()
let view = OpenUIView(state: state, library: library)
~~~

使用 SwiftUI 的 Text 时显式 import SwiftUI。需要扩展现成 OpenUI 目录时从 OpenUIComponents.library() 开始，使用 OpenUIComponentLibrary.extending(adding:overriding:removing:)；该入口将语言 authoring 交给官方 library.extend，保留 renderer 的实际来源。

参数顺序决定位置调用，不排序 schema 属性。命名 slot 通过 OpenUIParameter.slot 声明，组件使用 Context 渲染对应子项。结构、布局依赖、占位和身份字段通过 component.presentation(...) 元数据表达，不让公共 renderer 按组件名猜测。

只缩小新生成范围时，从实际定义派生 writer；已存消息应使用与自身程序匹配的 reader 和注册表。移除 renderer 后不能靠保留旧 schema 恢复原生组件。人工编写的说明和示例需同步裁剪，不能声称 schema 删除会自动改写说明文字。

### 生成与组合

OpenUI 的通用组合建议和可解析示例维护在 [prompt-options.mjs](../Tools/Presentation/prompt-options.mjs)，由 [catalog.mjs](../Tools/Presentation/catalog.mjs) 连同固定上游 schema 生成资源；生成时检查全部示例可解析，并记录该输入的哈希。组件名、参数顺序、枚举、默认值与绑定没有随呈现建议改变。`OpenUILibrary.openUI()` 使用此组合预设；从底层组件库自行生成 prompt 时仍由调用方显式选择预设。

连续解释使用 TextContent/Markdown，章节使用 Markdown 标题，对象使用已有对象标题入口。column Stack 的默认组合建议为：标题到内容用 `s`（8pt），相关段落用 `m`（12pt），章节之间用 `xl`（24pt）；SDK 保留输入显式 gap，不按标题文案或嵌套深度自动加边距。回复、普通章节、段落、图表与表格默认直接排版；具体对象需要独立比较、选择或操作边界时才使用 Card。一个标题或数字不足以成为建卡理由，已有表面的对象集合不再外套 Card。ListItem subtitle 承载辅助信息，核心解释使用正文。

同一决策区区分主要动作、候选和参考；名称、标签、说明各自提供信息，避免重复同一句话。FollowUp 直接放在回复末尾的 Stack 中；Form 默认呈现一张完整任务卡，Buttons 是第二个参数，生成时不再给 Form 或各 FormControl 外套 Card。图表承担数量关系，表格承担精确比较，不因组件可用就重复展示同一结论。普通解释不放进 Callout，图片错误及控件能力也不由生成内容补写教学文字。

素材必须来自用户或工具；假设示例明确标注。SVG 使用贴合内容的 viewBox 和适合手机阅读的短标签，长解释放在正文。组件根据现有类型与槽位区分用途，不读取 URL、案例名或文案关键词决定版式。历史输入保持原样，这些建议影响之后的生成，不会重写已存消息。

## 主题与呈现

OpenUITheme 定义语义 token，OpenUIThemeValues 提供当前解析结果；OpenUIPresentation 管理呈现选择。OpenIntelligentUI 的主题不通过本库配置。

~~~swift
OpenUIView(state: state, library: library)
    .openUITheme { theme in
        theme.spaceM = 20
    }
    .openUIPresentation(OpenUIPresentation())
~~~

主题通过同一个 typed Context storage 传递。context.theme 和 context.presentation 读取 OpenUI 的值；自建组件需要相同规则时使用对应 Context 扩展。子树覆盖保留同层其它 typed values；不要用高频几何或计时状态反复改写全局主题。

`tableAppearance` 可为 OpenUI Table 和 SDK 内的 Markdown 表格共同配置网格线、表头与首列背景、内容背景、可选字体和圆角；不设置时保留默认表格。圆角未单独设置时使用 `radius3xl`；使用该表格外观的 Markdown 短表铺满可用宽度，宽表保留列对齐并支持横向滚动。EntityList 默认使用共享标签列，文本值共用起始位置，数值沿右缘对齐；标签较长时允许换行。`markdownListItemSpacing` 控制 SDK 内 Markdown 列表项间距，不影响宿主自己的 Markdown 渲染。这些呈现调整不改变组件参数或历史数据。

`markdownEmphasisFont` 可为 Markdown 的加粗文字指定字体族与字重；字号仍继承所在段落或标题。不配置时沿用默认加粗方式，原文及链接语义不变。

~~~swift
var theme = OpenUITheme()
theme.tableAppearance = OpenUITableAppearance(
    gridLine: .gray, headerBackground: .gray.opacity(0.1), background: .white)
theme.markdownListItemSpacing = 15
~~~

颜色使用语义角色与 Apple 平台外观，保持文字、边界、强调和状态的职责。图表序列色不复用为业务状态色。字体、圆角、间距、媒体比例与按钮形状使用所属 token，不让不同类别自行创造一套视觉层级。

紧凑模式和大字号不压缩来源文字、价格或字段标签。卡片与列表的组合由输入程序决定，组件不把完整内容裁成统一摘要，也不为单个 Gallery 场景硬编码布局。

### 阅读层级与可用宽度

默认呈现按内容角色组织：章节标题统领对象，正文承载核心解释，辅助文字用于元信息。使用既有语义 token 调整组件配方，不全局放大字号或增加一套主题。

默认界面保持内容优先。资源失败、辅助阅读模式与控件能力不自动生成一段说明、徽标或额外工具栏；采用安静占位、原生滚动和无障碍语义。作者明确提供的标签、说明及用户可以处理的校验错误继续保留。

- CardHeader 使用章节角色；InlineHeader 与图文对象保留对象标题角色。恢复原有 20 / 18 pt 默认值；宿主可以完整覆盖字体，容器不根据嵌套层数或文案长度改写文字角色。
- Steps 的解释属于正文。ListItem 的 subtitle 继续表示辅助信息；需要多段核心解释时，组合 TextContent/Markdown，而不是把正文都放进小号副标题。
- 主 Metric 与行内数字按角色区分；数值和单位保持完整，超长金额不缩字号或截断小数。
- OptionCards 最小阅读宽度默认采用 136 pt，并按字体尺度增长；宿主可以设置更宽的选项，辅助阅读字号继续单列。列数由当前位置可用宽度决定，不随流式文案字数反复变化；长说明自然增高，不靠缩字维持列数。
- Form 默认使用一层 Card 表面及其内边距，组织同一任务的字段和动作。宿主嵌入已有面板时可设置 formShowsCardSurface = false；生成规则默认直接使用 Form，不重复套 Card。渲染器不按嵌套层数擅自删除显式 Card，输入控件仍保留自身边界。
- 默认只显示作者提供的字段标签与 hint，不自动追加 Required、可多选或重复日期范围摘要。必填、选择模式和完整日期范围保留无障碍语义，原始校验规则仍是唯一依据；错误按已有校验时机展示。
- InlineText 主值与辅助说明使用既有 titleDetailGap，空说明不产生额外间距。Chips 与 FollowUp 的多行标签限制圆角，避免文字落入高胶囊的弧线区域；不缩字、不隐藏选择状态。普通 Tabs 使用文字与选中下划线。日期样式用圆角选中底和上下排列的星期、日号。
- 水平 IconText 的图标槽与文字块顶部对齐，副标题换行不改变图标位置；显式图标尺寸、颜色和槽内边距保留。ImageText 继续让图片与整段文字居中，显式 vertical 布局保留原有排列。

默认值是可覆盖的呈现策略。显式尺寸、布局方向与输入内容继续按契约处理；Form 唯一提交的局部满宽规则见下节。

### 文字角色与 Callout

文字的用途决定字体、字重、行距和前景；容器负责排列、分组与内边距。普通阅读内容不因进入 Card、列布局或深色外观改变含义，不自动获得底色、边框或提示标签。字号小不等于信息次要，字号大或加粗也不自动获得无障碍标题语义；标题由实际标题入口表达。

默认字体恢复到本轮文字调整前的基线（`3310e3d`）；点值对应默认字号，宿主的完整字体覆盖继续优先。iOS 沿用此前统一的 body Dynamic Type 缩放基准，不为每个组件或字号再分配一条独立缩放曲线；macOS 默认值保持不变。

| 用途 | 现有字体 token | 默认字体 |
| --- | --- | --- |
| 文档标题 / Markdown H1 | textHeadingMd | 26 pt semibold |
| 章节 / CardHeader / Markdown H2 | textHeadingSm | 20 pt semibold |
| 对象 / InlineHeader / Markdown H3 | textHeadingXs | 18 pt semibold |
| 核心解释与 Callout 正文 | textBodyDefault | 16 pt regular |
| 显式 large / lg 正文 | textBodyLg | 18 pt regular |
| 小号正文、紧凑解释与辅助说明 | textBodySm | 14 pt regular |
| 图注、元信息等既有小字号入口 | textBodyXs | 13 pt regular |

小号正文与辅助说明复用同一字体，信息优先级由各自的语义前景表达，不额外增加仅相差一号的字体 token。大号正文继续使用正文角色，不增加标题边距或无障碍标题标记。默认正文行高恢复 1.5 倍，辅助文字 1.45 倍，元信息 1.4 倍；标题保留原有 1.25 / 1.30 / 1.35 倍关系。行高仍以实际字体度量为下限，显式 lineHeight / lineSpacing 优先，不通过固定高度裁切文字。加重字体仍是独立的完整配置：宿主对 heavy token 的字族、字号、字重、行高与字距覆盖继续生效，不从普通字体偷偷重建。既有 Text 的 sm / md 别名、TextContent 的 small / large 变体以及解析模式保持原契约。

NativeTextStyle 与 NativeTextRole 统一原生文字和 Markdown 的字体配方；Markdown 内部字体需要显式接入配方，不能只依赖外层 SwiftUI font。段内行距由文本 renderer 管理，兄弟内容的 gap 由父布局管理，组件内边距由其表面管理，页面左右边距由宿主管理。避免用多层 padding 弥补不一致的文字度量。

Callout 表达与当前内容相关的独立提示或反馈。普通解释继续使用 TextContent/Markdown；Callout 不自动补写“提示”“注意”或“信息”标题，也不根据文案关键词推测状态。可见标题和正文只来自输入，完整换行，不按固定行数裁切。

- 恢复原有文内说明样式：neutral / info 共用中性 3 pt 竖线和 16 pt leading inset，不显示额外信息图标、整块底色或边框。上下间距为 8 pt，标题到正文使用 4 pt titleDetailGap；标题复用 16 pt 的 textBodyDefaultHeavy，正文复用普通正文，均使用主文字色。
- 显式 success、warning、error / danger 保留状态图标和局部语义颜色，不叠加竖线、整块底色或阴影。辅助功能保留状态含义，颜色不是唯一辨识方式；空白标题不占位。
- TextCallout 保持持久展示。Callout 保持原有 reactive 契约：只有可写 visible 绑定参与自动隐藏，在可交互且可见时等待 3 秒写入 false；没有绑定时不凭空隐藏。换源、不可交互和取消仍遵循原有生命周期。

这里的组件 Callout 与 SwiftUI 的 Font.callout 是不同概念；不会仅因为内容是提示就套用一个固定字体或改变其业务生命周期。

## 状态、字段与动作

组件通过 OpenUIComponentContext 的 value/string、children/slot、binding、field 和 action 方法接入；不直接改写整份 state 或绕过 Context 执行动作。context.string 是显示便利方法，精确字符串与键使用 OpenUIString/Value，不能在协议、身份或资源键上引入 Unicode 归一化。

可写控件区分文档 Store、局部编辑草稿和提交结果。Select、Radio、Checkbox、Switch 的用户选择须在首次操作后反映到当前展示；Store-only 的更新也必须使叶子 View 刷新。无可写绑定的字面值不能被当作可写状态。

字段验证通过共享规则与 Context 执行。被拒绝的草稿不能因其它 Store 发布而提交；源码替换使原草稿、旧动作和旧异步结果失效。EditableTable 的本地交付回执不代表远程持久化。Slider 的离散格点考虑 minimum 与 step 的精度，范围末端、拖动和连续文本按各自已有规则校验。

原生字段使用完整的表单名与字段名确定初始化、焦点及校验注册的生命周期；普通值更新保持控件身份。EditableTable 与 Slider 同时用这个键选择文档中的草稿，动态切换名称后读取对应字段，切回时恢复该字段未提交的编辑。流式名字尚未闭合时只持有挂载期预览草稿，不为每个字符串前缀建立永久编辑记录。Slider 仅在原字段确认接受写入后清除 pending，拒绝或同步回调中新产生的编辑仍保留。新字段挂载，以及同字段初始值流式补全时，初始化和校验注册都使用当前输入；只在 Store 缺失该字段时初始化，不覆盖已有用户值。完整初始值应在字段闭合后进入 Store，无需等待整份文档 complete，不能只凭界面的值回退认定初始化成功。具体挂载、重入和流式回归见[验证说明](validation-and-security.md#sdk-正常接入与生命周期审查)。

UI 特有的点击项上下文可以由组件提供；通用状态、动作执行顺序、异步取消和文档就绪检查由适配层负责。表单和资源的精确名称保留 UTF-16 语义。按钮、卡片动作与本地选择在拖动/分页结束时不能误派发激活。

### 表单单提交与继续对话

Form 自己的 buttons 槽总共只有一个稳定声明的标准提交 Button 时，按钮铺满字段列，遵循 Form 面板的 inset；宿主关闭表面时不保留该层 inset。提交包括继续对话、mutation 与自定义提交动作；纯导航、Set/Reset 和 Query 不据此自动铺满。

满宽与 variant/role 独立，保留来源声明的 primary、secondary、tertiary 或 destructive 样式。单项 row 与 column 均可满宽；多个动作、Form 外按钮、字段内部动作、商品 footer 与表格单元格继续使用原布局。只有列表和必要参数稳定后才认定“只有一个”，不将流式暂时出现的首项当成唯一项；布局变化保持同一控件子树。

继续对话保留完整文字，标准按钮与 FollowUp 分别采用适合其场景的呈现：

| 场景 | 默认呈现 |
| --- | --- |
| 标准继续对话按钮 | label 与箭头组成居中的内容组，继承原按钮字体、前景和表面 |
| FollowUp | 按内容宽度排列的紧凑浅色胶囊；空间不足时自动换行，长问题在胶囊内自然折行；默认无箭头，保留独立触控目标 |
| Performing | 文字和触控尺寸保持稳定；标准按钮在原附件槽显示延迟进度，FollowUp 保留问题及执行中的无障碍状态 |
| Pending / Disabled | 区分尚未就绪与宿主禁用，均不冒充已完成；辅助功能说明状态 |
| 校验失败 | 先展示并定位字段错误，不派发继续对话 |

整行或整个按钮都是同一个点击目标，箭头不形成第二个按钮。图标使用 forward 语义并遵循 RTL，只作为装饰朗读；按压、hover 和键盘焦点有轻量反馈。长中文自然换行，触控尺寸与可见外形分开处理。

标准按钮的箭头按真实且已就绪的 action 分类，不按中文 label 猜测：明确的 continue_conversation、最终 nil/null 的默认继续对话，以及本地 Set/Reset 配合单个 ToAssistant 可以采用；混合 mutation/custom/open_url 等外发意图时保守保留原动作表达。分类不执行消息 AST 或触发工具。

可见 label、实际 message、params/context、formName 与派发时 formState 完整保留。ToAssistant 的 message 可与 label 不同；legacy 对象继续使用原 dispatcher 的消息来源。提交仍先刷新草稿、再校验、再派发。SDK 的 performing 只覆盖本次 await，不承担整轮 Agent 回复状态，也不自动宣告远端保存成功。

### 控件完成度

- 范围 Slider 的两个端点使用明确的上下限语义；空间不足时内部数值布局转为纵向，保留草稿与焦点。
- 普通 Tabs 保留横向滑动的标签行，以主文字色和既有 2 pt 间距 token 绘制选中下划线，不显示两侧操作箭头。单个标签宽度包含水平内边距，普通字号最多两行并在尾部截断，辅助阅读字号完整换行。点击、绑定更新、容器及字号变化会将选中项滚入视口；手动滑动不会被强行拉回。下划线不参与高度分配，RTL、末端位置与键盘激活按原生行为验收。
- DateRange 的清空操作明确为“清空日期范围”，保留整个范围清空的既有数据语义；自动调整另一端后，两个端点同步显示最终日期，组的无障碍值提供完整范围，不追加第三行日期。Cancel 不保存草稿，Done 才确认。
- 选择卡、Tabs、FollowUp 具备一致的最低按压和焦点反馈，禁用说明与错误信息保持可辨。适用文本字段从已有声明顺序获得下一项/完成流程。

## 布局与流式

父容器拥有分配的可用空间，子组件消费当前位置的 proposal。缩放只影响观看倍率，逻辑宽高控制实际排版。尺寸拟合与旋转不能重新提交源码或清空用户输入。

- 缺失引用、尚未完成的数据和已闭合但为空的数组分开处理；不为未提供内容虚构图文格子。
- 稳定节点、局部状态、选择和资源身份应在增量流中保持。流式追加不能重建整棵文档环境。
- 结构元数据可以保留已声明的槽位，但不承诺所有程序都有“有序就绪前缀”；实际可见性遵循官方解析结果和原生 readiness。
- 已完整的控件可在其它内容继续流式时交互，未完成动作仍须阻止执行。
- 源码或布局未完成诊断仅保留在运行时，不作为可见正文或辅助朗读提示。Stack 在终态继续保留已可读的前缀，不追加诊断尾注；生成中的等待和真实组件、数据或资源失败仍保留相应反馈。未完成内容及动作不会因此被标记为完整或开放交互。容错前缀不代表完整答案，宿主按 [终态与诊断](../README.md#终态与诊断) 决定最终消息是否接受与展示。
- 文本字段收到最后一段后，即使只有其它节点继续生成，也须继续推进到原生文本缓冲及 Markdown 准备链路。文字与流式状态使用同一次更新的值；48ms 呈现合并只降低重排频率，不能让字段等待 `complete` 才补全。读取与尺寸拟合仍不创建任务或发布状态。
- 卡片、图片、图表、表格和窄屏行布局按本库规则等待必要尺寸或数据，不靠改写来源内容绕过就绪条件。
- 标准 Card 的增长与最小列宽由父 Stack 在直属子项边界分配，不依赖多层动态 renderer 传递布局标记。clear Card 继续使用 160 pt 阅读列宽，其他表面使用既有卡片列宽，并沿用 body 字号缩放；默认字号、350 pt 有效宽和 12 pt 间距下，两张 clear Card 各占 169 pt，图片、长标题与正文在各列内排版。更窄或更大字号时按原规则换行，不强制双列；替换 Card renderer 的宿主继续拥有自己的布局约定。
- 宽度、主题和 Dynamic Type 变化只改变布局与呈现，不产生新的文档身份。滚动容器和消息列表归宿主。

完成的长文档仍可因宽度、字体、Query、字段和资源变化重新布局，不能用 `complete` 冻结几何。Stack/Card 的 Flex 布局只在自身 `Layout.Cache` 中保留最近一次有效 proposal 的 frames；测量与放置条件一致时复用，布局或子视图变化时清空，实际放置宽高不同则重新计算。不保存子视图、Context 或整份文档，也不维护多尺寸缓存。

标准 Table 在一次 body 中取得一份当前列与分页派生值，布局、表头和单元格消费同一份结果。完整列的数据数组复用不可变 `OpenUIArray.values`；`stableColumns` 继续只用于数据等待、失败或源码未完整时的已读内容回退，正常完成后的状态与 Query 更新仍从当前 Context 读取。

这些措施减少现有呈现路径中的重复工作，不改变节点身份或文档生命周期，也不提供视口裁剪。长内容是否需要分段呈现，须结合宿主消息行回收、阅读锚点、动态高度与表单状态验证；不能把同一 Lang 程序拆成独立 State，或直接把离屏内容长期替换为固定高度。当前证据、公开压力样本与验收边界见[验证说明](validation-and-security.md#完成长文档的滚动与布局)。

## 文本、媒体与原生差异

Markdown 与代码使用固定的 typed adapter，不在组件里创建任意 JS 环境或执行来源脚本。公式与代码资源随包分发，许可与安全策略见验证说明；文本组件不得提交源码或写入文档状态。

Markdown、TextContent 和行内富文本在同一 remark 链路采用固定版本的 CJK 强调解析扩展，支持 `**中文句号。**后续文字`。准备结果通过 CommonMark 安全的字符引用传给原生 Markdown renderer，保留文字、链接、代码及转义的字面含义；不在原始 Lang、模型输出或历史内容中插入空格、不可见字符或改写标点。

Markdown 首次后台准备尚未返回时，同配置的连续追加复用已经可读的同步前缀，不在每次 body/拟合中再完整解析增长中的文本。后台仍逐次交付已经完成的中间结果，再处理最新 pending；不等待语言流 complete。非追加纠正、来源说明、模式、字号或颜色变化使旧工作失效，正文立即使用对应输入的 fallback。首次和没有可复用 prepared 的同步读取仍可读；已有兼容 prepared 的前缀在离开、重新进入时可以保留，读取本身不启动任务。

有效后台结果覆盖同步 fallback 后，释放该 fallback 的源码与解析树。若 body 已先读取更新的纠正文本，则保留该纠正直到对应结果准备完成；取消或迟到结果不能清除当前可读内容。

原生图片读取宿主资源 Context、baseURL、loader 与鉴权作用域，受并发、响应及解码预算约束；作用域变化需同时影响缓存、View task 与已解码内容身份。比例、加载、失败、重试与预览属于组件视觉，不将该保证扩大到 WebKit/Markdown/MapKit 的所有网络请求。

图片的稳定身份包含精确来源、baseURL、loader、授权作用域、资源限制和显式重试次数；实际请求在一次加载尝试内冻结。不能在布局、状态回调或完成校验中重新调用可能生成新 nonce 的签名器。请求快照继续依附既有文档媒体缓存并有容量上限，显式重试与作用域变化建立新请求，文档重置清理快照；图库选中/状态及背景图状态使用同一稳定身份。

普通封面、图文卡和图库根据布局后的实际宽高与屏幕倍率确定解码需求；未得到有效尺寸时不先按默认 2048 px 下载并解码。固定缩略图使用声明尺寸，原比例图片按展示宽度计算，预览的显式像素请求继续有效。ImageIO 读取同一份响应的源尺寸及 EXIF 方向后，再按 fit/fill 计算所需最长边；竖图填横卡时需保留被裁剪方向的足够像素。尺寸分档减少同档微小变化，跨档的在途请求仍可能更新，不能等同于完全消除几何变化的工作。完成缓存按源比例检查是否足够，较清晰的结果不会被较小结果替换；源图字节、像素及解码上限继续有效。

这属于客户端降采样，默认仍下载原始 src 的完整响应；没有自动拼接 CDN 参数、引入图片代理或改变 Lang 输入。要减少原图传输字节，需要宿主图片服务提供匹配尺寸的资源，不能把解码像素减少写成下载量已经减少。

同一个合并中的图片加载任务对安全 GET/HEAD 的已知暂时网络错误，或可识别的 HTTP 408/429/500/502/503/504，最多自动再试一次。等待不占网络/解码准入名额，保留同一冻结请求；支持短 Retry-After，无法解析或超过自动恢复等待范围时保留手动处理。取消、换文档、换鉴权和限制变化使等待或迟到结果失效。超限、解码失败、无效来源、鉴权失败和 404 不自动重复下载；自定义 loader 只返回笼统错误时不猜测其 HTTP 原因。自动恢复期间维持加载占位或已有图片，耗尽后仍可点图显式重试并取得新的签名请求。

默认 loader 保留原 URLError 类型/代码，并补充不含 URL 的 HTTP 状态与 Retry-After；预算错误区分 responseBytes、imageSourcePixels、decodedImageBytes。Console 的 `dev.openui.swift` / `Media` 调试记录只包含固定失败阶段与数值，不记录图片地址、请求头或正文。Instruments 的 `org.openui.swiftlang` / `Runtime` 增加 Image decode、Markdown preparation、Markdown fallback 区间，沿用同一按需记录机制，用于和既有 Parse、Root evaluation、Native projection、Live index 等区间对照。

单图与图库预览根据实际视口、显示缩放和已确认的放大比例申请解码尺寸，先应用资源像素上限再决定是否加载。已有缩略图可作为临时画面，高清结果到达后替换；同一资源的尺寸升级复用冻结请求，等待期间保留已有像素，缩小视口不降低已接受的清晰度。来源或授权作用域改变后不得继续显示旧资源。

图片背景卡片的局部深色与白色文字只作用于内联内容，不传入完整查看的呈现层。单图与图库预览使用同一外观下配对的主题前景和背景，标题、关闭按钮及说明保持可读；横图继续按原比例完整显示，不为填满竖屏裁切图片。

图片预览继续使用 sheet：顶部标题与关闭，中间完整原比例图片，底部说明；图库在此基础上保留切图与缩略图导航。共用说明区按短文的自然高度收缩，长文超过既有五行、最多 240 pt 的阅读预算后才滚动，不为一句说明固定预留整块高度。普通图片、图文卡、列表图片、Markdown 图片、地图缩略图与视觉卡均沿用同一个单图预览入口；图库复用同一说明区，不逐组件叠加另一套查看器。

图库大图仅挂载当前页和相邻页，缩略图条惰性创建，离屏缩略图释放自身持有的解码结果。图库父视图只保存状态与选中项，不再另存全部图片绕过有界媒体缓存。远距离选图直接切换到目标页，避免沿未挂载页面播放空轨道；普通卡片及表单轮播保持原有子树身份策略。

Map 表达来源坐标与选点，不表示真实导航、实时交通或已完成业务操作；当前 Map 组件整体要求 iOS 17/macOS 14。空坐标、准备中和较旧的受支持系统使用稳定地图区域的安静占位，状态与版本要求通过无障碍语义提供，不塌成一行技术说明。SVG 要求有效 viewBox，使用内联内容或 HTTPS src，拒绝活动内容和外部引用。

### 地图与媒体

- `Map` 默认将输入经纬度原样交给 MapKit。需要转换时，由已知底图坐标系的宿主显式设置 `OpenUIPresentation.mapBasemapCRS`；转换的来源取 `Map.crs`，省略时按 GCJ-02。
- 转换范围使用随包发布的 [Natural Earth v5.1.2 地理轮廓](https://github.com/nvkelso/natural-earth-vector/blob/v5.1.2/geojson/ne_50m_admin_0_map_units.geojson)，按 [高德坐标覆盖说明](https://lbs.amap.com/faq/advisory/others/39840/) 选取地图单元。覆盖范围外保留输入坐标。轮廓用于排除范围外的点，不用于推断当前 MapKit 底图；资源由 [生成工具](../Tools/Presentation/build-map-coordinate-coverage.py) 固定来源和校验值。
- 流式直绘在地点名和经纬度完整有效时显示该点。已挂载地点卡的 `imageSrc` 字段一旦收全即可加载缩略图，说明和后续地点可继续流入。详情地址在点位语句完整后读取。显式设置绘制目标时才等待来源 `crs` 确定。同一份点位输入和绘制目标共用一份有序地点列表，图钉与名称菜单按有效点位顺序编号，选择由地点身份维持。
- 地图内嵌视口高 320–360 pt。地点沿用列表顺序编号，图钉尖端对齐坐标；选中放大的白色图钉配黑字，其他图钉用黑底白字。地点名显示在底部联动卡片中，图钉保留地点名称和选中态的无障碍语义。
- 普通无绑定地图默认选择第一处有效地点并显示地点卡，初始相机仍展示全部点位；用户点选后聚焦。点集新增或重排时保留仍有效的本地选择，选点被删除才回到新的首点。宿主显式选择绑定优先，null 或无效值不被组件改写。关闭完整查看保留选择，换文档清理旧选择、相机与展开状态。
- 缺图在原透明缩略图槽中央显示 mappin.and.ellipse。没有额外色块、圆盘、描边或阴影；地点卡片自身的表面继续保留。无 URL、等待、失败、恢复与成功淡入遵守同一占位规则，照片加载不挤动相邻文字。
- 紧凑地点卡的圆角比地图容器小 9 pt，使用主题加重的标题和说明文字展示地点摘要；箭头直接打开该点的有效 URL，无 URL 时保留原有稳定空位。地图展开仍进入完整地图，不额外增加地点详情 sheet；旧文档回调与未就绪内容不能派发外链。
- 内容图、缩略图、图文卡与图库失败时使用 16 pt photo 图标；宽度至少 160 pt 且单行文案完整放得下时，再显示本地化的“图片暂不可用”，放不下就只留图标。内容图使用现有浅色媒体表面，缩略图沿用所属容器。不显示 alt 正文、详细错误或独立 Retry 按钮；有有效请求时点击整个占位重试，无地址或无效地址不发起空请求。地图保留所属组件的无底色 POI 占位。有限自动恢复按上述传输失败规则进行，尺寸测量不刷新签名或把永久失败当作可恢复错误。
- `imagePlaceholderBackground` 单独控制图片与 SVG 加载占位、图片成功淡入时的背景；未配置时使用 SDK 的默认图片占位色，随系统明暗模式变化。其他组件继续使用 `sunk`，图片失败状态仍沿用其所属容器的背景。
- 加载与失败内容在同一媒体槽位内互斥显示，加载期间不挂载失败图标或文案，也不通过整层淡出露出下面的失败状态。宿主提供透明媒体表面时同样只有一套占位；保留加载 shimmer 与成功图片淡入。图片请求是否失败与占位如何绘制分开定位，不能仅凭失败占位把网络或鉴权错误归给客户端或 SDK。
- 独立 Image / ImageBlock 恢复固定封面比例，默认 16:9，并填充裁剪超出部分；加载、失败与成功保持同一声明几何，完整原图通过媒体预览查看。宿主的 coverAspectRatio 继续生效。Markdown 内嵌图片仍使用已有原比例路径，图片来源变化不能借用上一资源的尺寸；不按 URL 或图中文字猜测用途。
- 图片图库统一使用 max(thumbnailSize, minimumCompactCardWidth × readingScale) 确定最小列宽，默认至少 160 pt，辅助阅读字号单列。纯照片与带说明的图库沿用同一列宽规则。
- 图库最多展示前五张缩略图，点击可预览的图片进入完整集合；不增加总数、查看全部按钮、箭头或重复 footer。未就绪引用保留已有槽位与资源身份。
- SVG 直接点击已加载的图形进入完整查看，不在正文图形下方增加独立展开按钮、工具栏或空行。点击区域与图形重合，保留无障碍名称与操作；嵌在有主动作的卡片内时，图形保留父卡片点击，通过上下文菜单与无障碍动作预览，不嵌套 Button。缩放和平移说明只放入无障碍提示。加载或失败保留安静的图形区域，详细错误和 alt 不成为可见说明段；远程加载失败点击占位重试，创建新的签名请求并跳过失败的本地缓存。有效文档的 WebKit 呈现失败也点击原占位重新加载。只有 View 任务本身取消时才静默退休，传输层意外返回 CancellationError 仍进入可恢复失败状态。保留 viewBox、安全边界和全屏缩放能力；作者提供替代描述和主题友好的图形颜色，renderer 不自动反色或虚构图意。

### 图表、表格与图文对象

- 常规图表保留 250 pt 默认高度基线，饼图/径向图与单条比例图继续各自的高度策略；按类型、标签、字体和数据量调整密度，保留合法的显式高度。横向柱图的分类文字参与同一布局测量，完整换行，按类别数量和所需行高增加自然高度；文字区最多占可用宽度的一半，每根柱对应一个可见分类，不隔行隐藏或整组省略。标签、绘图和命中使用一致的几何。
- 比例条的绘制与命中共享几何。合法全零数据有明确表达；选中图形与检查详情对应。Line/Area 的图形与图例增加按源序列身份分配的线型，隐藏系列后保留颜色和线型；其他类型继续通过现有图例与检查详情辨识。
- 普通检查使用轻量浮层，尺寸受图面与图例的实际可用区域约束；放不下时隐藏浮层，不挤压或截断完整值，也不生成“查看完整数据”的教学文字。完整数据通过图表上下文菜单和无障碍动作打开，详情可滚动阅读全部系列，包括暂时隐藏的系列；正文不再附加“查看图表数据”按钮或为它保留高度。iOS 点按检查当前数据点，长按交给系统上下文菜单；桌面继续保留已有指针检查，图例选择与纵向滚动保持各自的交互。
- 表格保留完整换行、数值对齐、原生横向滚动和自定义单元格，不默认附加“按行阅读/表格视图”按钮或横滑说明。辅助阅读字号自动使用按原列标题逐项阅读的排列，不默认把任意第一列当作主键。两种排列复用同一 cell 子树；编辑默认列宽考虑字号，显式列宽与修改/保存/冲突状态继续保留。
- VisualCardItem 与背景图 ContextCardItem 保留背景照片和图上叠字的构图，Tag / 标题与主体按原有上下关系排列。能容纳的普通文案继续叠在照片上，不按“半张图”的阈值提前改为上下图文；确实放不下或使用辅助阅读字号时沿用原有的图下阅读排列。叠字遮罩使用分段黑色渐变：顶部 50%，上部短段 46%，中部降至 12%，下部回升至 56%，底部 60%；让照片主体更明亮，并在上下文字附近保留托底。普通 Image/ImageBlock、未加载照片以及图下文案不增加这层遮罩。照片比例与图文稳定子树保持，流式追加不重建图片请求或裁掉文字。

Charts、原生选择器、滚动与表格采用 Apple 平台实现。确有原生差异时保留输入语义并按实际 View 验收，不能把“来源相同”写成逐像素等价。来源映射以 Catalog 和固定生成输入为准，历史差异在 Git 中，不维护另一份逐文件映射文档。

### 阅读与 Callout 的明确方向

普通解释与核心论述由 TextContent/Markdown 承载，章节标题和对象标题沿用已有角色。ListItem 的 subtitle 表达辅助信息；核心解释通过正文组合，生成建议避免把所有描述放进小号副标题。大号正文仍是显式正文选项，不自动承担章节标题。

Callout 与 TextCallout 共用已有轻量视觉语法，围绕独立补充、限制条件或明确状态使用。neutral / info 延续细线与正文的组合，标题仅在输入提供时显示；success / warning / error 使用局部状态图标与语义颜色。数值与现有样式见上文“文字角色与 Callout”，不另建一套字体、底色、标签或标题规则。

两个组件保留各自的生命周期：TextCallout 持久展示；Callout 的自动隐藏仍依赖可写 visible 绑定、可交互且可见等既有条件。空标题、只有正文、长中文、流式追加及状态切换都进入本批验证。视觉统一不改动绑定与业务语义。

间距按关系分配：段内由文本 renderer 管理，兄弟内容由父布局管理，表面内边距由容器管理。将相同内容的整段 Markdown 与拆分节点放在同一组合约定下核对，避免叠加标题 padding。卡片用于独立对象、可比较候选或有明确边界的操作区域；连贯解释与一般章节优先直接排版。

历史 Lang 中显式的 Card 与 Form 仍按输入渲染，SDK 不根据祖先或文案自动拆除容器。生成规则影响之后的模型输出，宿主的自定义提示与既有表面覆盖需与同一约定一致。

既有呈现回归继续覆盖图库列宽、封面裁切、表单表面、选项列数、Tabs 标签宽度和地图绑定。此前在失败→重试测试中增加了透明媒体表面的加载像素断言，并覆盖预览短说明、图库补充说明、长文和受限高度。图片与正文优化阶段增加显示尺寸、共享自动恢复和可控 Markdown 准备回归；测试注入仍执行同一 document 控制流，默认准备继续使用既有后台 worker。原有 fixture 与断言保留。

此前组合调整的检查记录在忽略的 `outputs/verification/rc20-selected-presentation/`：生成目录重新构建并通过 `--check`，全部六个示例可解析，固定 84 个组件定义与 schema 保持一致，目录兼容测试 7/7 通过。占位/预览修复记录在 `outputs/verification/image-state-preview/`；媒体优化阶段记录在 `outputs/verification/openui-media-responsiveness/`。当前收尾证据与结果集中记录于[验证说明](validation-and-security.md#客户端复测收尾候选)，不把此前结果计作本轮原生验收。

原生编译与运行已经由 macOS CI 执行，不能继续把整轮工作描述为“尚未编译”。`1f070fe` 已通过深层数据前置回归、Release 尺寸拟合、iOS SDK 与 Gallery App 构建，但 OpenUI 和全库回归仍有失败，故不能视为整体通过。收尾候选保留全部原有几何、文本、身份和交互断言：文字/SVG 测试读取实际 SwiftUI 无障碍树，回退快照 marker 观察快照身份，图片尺寸探针按挂载实例管理并撤销退出视图的记录。独立原生日志证明原 Card 的 268 pt 内容宽度正确，旧失败由退出 Stack 的 300 pt 测量覆盖测试记录导致，因此不为它修改生产 Card 视觉。
